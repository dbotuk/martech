# SockLock ModGen — генератор модифікацій креативів зі скрипта-переможця

**Проблема.** Для $800 000 spend потрібно ~500 модифікацій на місяць, команда робить 240.
Половина з 3 годин на модифікацію йде не на моушн, а на ручне придумування хуків, перших фраз
і текстів на екрані. ModGen забирає цю частину: на вхід скрипт-переможець + болі з досліджень +
факти про продукт, на вихід — 10 готових брифів на модифікації з гіпотезою для A/B-тесту.

**Що на виході** (тека `out/<slug>/`):

| Файл | Для кого | Що всередині |
| --- | --- | --- |
| `brief.md` | Motion-дизайнер | Для кожної модифікації: тип, гіпотеза, хук VO (0–3 с), текст на екрані, зміни в тілі, CTA, який біль використано, що саме перемонтувати, оцінка часу |
| `mods.csv` | UA / Airtable | Ті самі поля рядками — імпортується в базу креативів як є |
| `mods.json` | Інтеграції | Сирі дані для Slack-бота чи Airtable Automation у наступній ітерації |

## Запуск за 2 хвилини

Потрібен Python 3.10+. Без API-ключа працює офлайновий рушій `rules` (шаблони + ваші болі й факти).
З ключем Anthropic вмикається рушій `claude` (Claude Opus 5.5, структурований JSON-вивід) — якість помітно вища.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

```bash
python modgen.py examples/winner_us_dryer.md --pains examples/pains.csv --product examples/product.md --n 10
```

```bash
export ANTHROPIC_API_KEY=sk-ant-...
python modgen.py examples/winner_us_dryer.md --pains examples/pains.csv --product examples/product.md --n 10 --engine claude
```

Корисні прапорці: `--engine auto|claude|rules` (auto бере claude, якщо є ключ), `--n 10`, `--lang de|fr`
(лише для claude: культурна адаптація, не переклад), `--seed 7` (відтворюваність rules), `--out out`.

## Вхідні файли

- **Скрипт-переможець** — markdown із розділами `## Hook`, `## Body`, `## CTA`, `## On-screen text`, `## Meta`
  (див. `examples/winner_us_dryer.md`). Так само виглядає картка креативу в Airtable, тож експорт у .md тривіальний.
- **Болі** — CSV `pain,quote,segment,source` (`examples/pains.csv`). Це те, що креативні маркетологи
  вже виписують із Reddit; ModGen нарешті доносить їх до модифікацій.
- **Факти про продукт** — `examples/product.md`: `## Benefits`, `## Proof`, `## Offers`, `## Verified stats`,
  `## Don't say`. Рядок може мати форму `коротка для екрана | довга для голосу`. Список «Don't say» —
  запобіжник від вигаданих тверджень і порушень правил Meta.

## Структура коду

```
modgen/
  inputs.py        читає .md/.csv → dict/list (розбиває markdown за заголовками '## ')
  schema.py        таксономія 11 типів модифікацій + JSON-схема одного результату
  engine_rules.py  офлайн: шаблони хуків × слоти з болів/фактів, детерміновано за seed
  engine_claude.py один виклик Claude API з output_config json_schema → список модифікацій
  render.py        додає id, що змінюється, оцінку хвилин; пише brief.md / mods.csv / mods.json
  cli.py           argparse, вибір рушія, друк підсумку
```

Таксономія типів: `hook_question`, `hook_pain`, `hook_claim`, `hook_social_proof`, `hook_curiosity`,
`hook_negative`, `hook_stat`, `hook_pov`, `onscreen_only`, `cta_swap`, `angle_swap`. Для кожного типу
зафіксовано, які елементи ролика змінюються і скільки хвилин моушн-роботи це коштує (30–90 хв
проти 180 хв сьогодні). Саме ця оцінка дає цифру «економія N год» у підсумку.

## Як міряємо успіх

Пілот: 2 тижні, 2 дизайнери, 3 скрипти-переможці. Половину модифікацій роблять із брифів ModGen,
половину як зараз. Порівнюємо в однакових адсетах за 14 днів.

| Метрика | Сьогодні | Ціль пілоту | Ціль через 3 місяці |
| --- | --- | --- | --- |
| Час дизайнера на модифікацію (таймер в Airtable) | 3,0 год | ≤ 2,0 год | ≤ 1,8 год |
| Модифікацій на місяць | 240 | — | ≥ 400 |
| ROMI модифікацій з ModGen проти ручних | — | не гірше ніж −5 п.п. | ≥ рівень ручних |
| Частка брифів, прийнятих дизайнером без переписування | — | ≥ 60% | ≥ 80% |
| Spend у джерелі «США: модифікації» | $230 000 | — | ≥ $380 000 при ROMI ≥ 125% |

Якщо після пілоту час ≤ 2 год і ROMI не просів більше ніж на 5 п.п. — розкочуємо на всіх шістьох дизайнерів
і беремо 3 тижні на повну версію. Якщо ні — зупиняємось, витративши 2 тижні й ~$50 на токени.

## Наступна ітерація

1. **Інтеграція з Airtable**: кнопка «Згенерувати модифікації» на картці переможця, бриф і CSV повертаються в базу автоматично.
2. **Зворотний зв'язок**: підтягувати ROMI кожної модифікації з Airtable і зважувати типи хуків за win rate, щоб генератор вчився на наших переможцях.
3. **DE/FR**: прапорець `--lang` уже є в рушії claude; наступний крок — чекліст культурної адаптації й рев'ю носієм, щоб запустити тести в Німеччині та Франції, які стоять 2 місяці.
4. **Батч-режим**: прогін усіх переможців за тиждень одним запуском через Message Batches (на 50% дешевше).

## Межі MVP

- Рушій `rules` пише англійською і тільки з того, що є в CSV та product.md; він для першого дня і для демо без ключа.
- Немає доступу до Meta/Airtable — вхід лише файлами. Приклади в `examples/` складено для домашнього завдання за структурою картки креативу, цифри в `## Meta` умовні.
- Оцінка хвилин на тип модифікації — експертне припущення, яке пілот має перевірити таймером.
